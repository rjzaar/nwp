## 7. Methodology — follow this, it is what produced the findings

**Every fix proves its test can fail.** Write the test, watch it RED against unfixed code, fix, watch
GREEN, record both. A test never seen failing is not evidence. Add a **negative control** wherever
"refuse everything" would also pass — several fixes this session were caught by exactly that.

**Verification gates the merge; it does not race it.** Fixes land only after an independent
adversarial reviewer reverts the fix and confirms the test goes red. When that ordering was violated,
a change reached main carrying a vacuous test.

**The recurring defect class is a check that cannot fail.** Confirmed mechanisms, all real here:
- `| head -1` on a multi-location audit
- `set -o pipefail` + `yq | grep -q` → SIGPIPE → rc 141 → guard never fires
- `mapfile < <(reader)` discards the reader's exit status
- gitleaks rc thrown away, cleanliness judged from a report that failed to exist
- empty config mapping to the weakest enum
- `[ -e ]` on a path the caller cannot traverse
- a test grepping for its own patch text rather than the property
- `[ -n "$a" ] && [ -n "$b" ] && [ "$a" -lt "$b" ]` inside a `for` loop **does not fail a bats test**

**Four rules for operator-facing claims** (from `feedback-verify-before-asserting` memory):
1. No literal in a command unless read off the target first — `stat -c %a` before `chmod`, grep the
   real line before the `sed`, check the version before the flag.
2. Before believing a negative, prove the probe can return a positive.
3. A permissions or network error (403, timeout, `000`) is "I could not look", not data.
4. The record is a hypothesis; the system is the fact — task lists, workflow summaries, prior notes,
   and my own earlier statements all get re-checked.

**Agent discipline:** push a branch as soon as anything is coherent. Work held only in a worktree is
lost when an agent dies; pushed work survives. **Treat every agent report as unverified and confirm
from `origin`** — this session had agents report total failure while their branch and MR existed.

## 8. Traps that cost real time here

- **`~/nwp` goes stale while agents merge.** `pl` runs from it, so it silently executes old code —
  this caused a wrong diagnosis (`pl secrets audit` "broken" when the checkout was 16 commits behind).
  `git fetch && git merge --ff-only origin/main` before trusting any `pl` output.
- **`.gitleaksignore` fingerprints are `file:rule:LINE`** and go stale the moment the file is edited.
  Regenerate with `gitleaks detect --no-git --report-format json`; never hand-edit line numbers,
  never widen an `[allowlist] paths` entry. A stale fingerprint fails **red**, which is the safe
  direction.
- **Rollback-registry CP IDs are hand-allocated** and three agents collided on CP19–CP22. Use a
  timestamped id (`CP-20260727-<slug>`).
- **`comm` is not enough for structured files.** A keep-both merge preserved every line while binding
  them to the wrong YAML key, leaving a blocking CI job untagged that no runner could claim. Parse
  and diff as data.
- **Stale branches:** `git diff` against an 18h-old branch showed ~9,100 deletions. Cherry-pick, do
  not merge, when a branch predates a busy day.
- **The git box has 3.8 GB RAM** and serves GitLab + 5 live sites. Never `gitlab-rails`. Keep remote
  work light and serial.
- **`nginx.service` is dead on the box by design** — GitLab's bundled nginx serves the vhosts.
- **Two `claude` behaviours:** the `co` alias is
  `nice -n 19 claude --dangerously-skip-permissions --model opus`, so permission settings are inert
  under it and it pins Opus regardless of `/model`.
